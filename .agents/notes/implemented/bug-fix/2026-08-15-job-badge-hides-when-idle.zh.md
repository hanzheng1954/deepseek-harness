# Agent Note：最后一个后台任务结束后，任务角标自动隐藏

Status: implemented

[English](2026-08-15-job-badge-hides-when-idle.md) | 中文

## 问题

会话头部的后台任务入口会列出该会话可见的全部 `ctx.jobs` 记录——活跃的与已终态的——并且只要还有任何记录存在，触发器就保持挂载。对一个任务已全部跑完的会话来说，这意味着一个常驻的「N 个后台任务」角标；而行是只读的（没有导航、没有详情），于是这个只剩终态记录的列表成了一页没人要的历史，无限期地占用头部空间：注册表只在 owner 销毁时丢弃终态记录，在一个长寿会话里这几乎等于永不丢弃。

## 决策

`JobListAction` 只在至少有一个活跃任务（`running` 或 `stopping`）时渲染。最后一个活跃任务结束时会先关闭列表，再把控件整体卸载——触发器与弹层一起消失。因此计数文案永远只报活跃数字——控件渲染期间它天然非零——空闲计数的 locale 键被删除。终态行仍然在列表内渲染，作为活跃行旁边的近期结果尾巴，其排序、状态词与冻结的耗时全部保持不变。

卸载完全依托现有的 `jobsBySession` 镜像：不需要新的 RPC，也不改动注册表。已结束任务的结果仍留在工作真正可见的地方——会话自己的工具行。

## 备选方案

**在列表里加「清除已完成」操作。** 显式路径：保留角标，让人类删除终态行。本次请求下被否决，因为它需要跨四层新增注册表 API、api-proxy 路由、客户端 remote 与 UI 入口，只为恢复一种「生命周期方案」免费到达的默认状态——而且一个只在有活干时才存在的角标永远不需要清理。

**保留触发器、只去掉数字。** 数字没了，但头部仍留着一个没有标签、只剩终态记录的控件——把要清理的杂物换了个名字，而不是清掉它。

**列表打开时过滤掉终态行。** 会在仍有活跃任务运行时丢掉结果尾巴，并且与已被钉住的排序与状态渲染相矛盾；否决。

## 后果

- 后台工作已全部结束的会话完全不显示任务控件，头部回到面包屑与工具区。
- 「列表打开时的终态翻转」不复存在：最后一个活跃任务结束时列表直接卸载，而不是翻成一条终态行。为此钉住该翻转的 settled 金样从 web e2e 场景中删除，场景现在钉住的是触发器与打开的列表一起脱离。
- 计数文案不再有空闲回退；`count.idle.*` 已从两份 locale 词典中删除。
- 单元与 e2e 覆盖钉住新的生命周期：只剩终态记录的会话什么都不渲染，杀掉最后一个活跃任务会让触发器连同打开的列表一起消失。
